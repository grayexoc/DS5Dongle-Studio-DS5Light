# DPI 처리 변경

CustomTkinter의 창별 DPI 조회와 논리 크기 변환 방식을 참고했다.
CustomTkinter 의존성이나 GUI 프레임워크 교체는 추가하지 않았다.
참고: https://github.com/TomSchimansky/CustomTkinter/blob/master/customtkinter/windows/widgets/scaling/scaling_tracker.py

- 창 생성 전에 Windows Per-Monitor DPI awareness를 요청한다. 실행 파일 빌드에도 같은 manifest를 사용한다.
- 글꼴은 Tk의 포인트 단위를 유지한다. 픽셀 크기만 DPI/96으로 변환하여 이중 확대를 피한다.
- Tk 글꼴과 ttk 스타일이 공용이므로 팝업도 메인 창과 같은 배율을 사용한다. 메인 창의 DPI가 바뀌면 열린 팝업의 크기와 컨트롤도 함께 갱신한다. 팝업만 다른 모니터로 옮겨도 자체 배율로 전환하지 않는다.
- 주요 공통 컨트롤: 원형 체크/선택, 스위치, 탭, 슬라이더, 카드 내부 여백, 섹션 제목, 컨트롤러 SVG 아이콘, 배터리 SVG 로고.
- ttk 버튼/입력/목록의 padding과 행 높이는 원래 값을 기준으로 변환한다.
- 모니터 이동/창 크기 변경 이벤트가 멈춘 뒤 120ms에 DPI를 확인한다. 상시 폴링이나 HWND 후킹은 추가하지 않는다.
- 창 크기와 최소 크기는 현재 모니터의 작업 영역으로 제한한다.
- 최소 크기의 논리 기준값은 작업 영역 제한 전에 보존한다. 작은 모니터를 거쳐 돌아와도 최소 크기가 누적 축소되지 않는다.
- 헤더는 로고와 상단 컨트롤에 필요한 높이를 사용한다. 공용 대화상자는 부모 모니터의 음수 좌표도 지원한다.
- 검정·금색, 설정 저장 형식, 햅틱·HID·오디오 경로는 변경하지 않는다.

자동 검사는 test_ui_dpi.py에서 DPI 변환·왕복·팝업 동기화·콜백 정리·음수 모니터 위치를 다룹니다. 실제 100/125/150/200% 모니터 이동, 잘림과 키보드 조작은 별도 실기기 확인이 필요합니다. 일부 개별 화면의 고정 여백은 공통 컨트롤 변경 범위에 포함하지 않았습니다.
