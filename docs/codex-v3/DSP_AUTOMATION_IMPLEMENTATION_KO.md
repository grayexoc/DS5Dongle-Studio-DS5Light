# DS5Light 오디오햅틱 DSP 및 자동화 작업지시서

## 목적과 기준선

작업 위치는 work/audit이다. 기존 미커밋 변경을 보존하고 AGENTS.md, V3_MASTER_SPEC_V2.1.md §5, STUDIO_FIRMWARE_SPEC.md, PHASE_STATUS.md의 최신 기록부터 확인한다. 목표는 배경음이 진동으로 섞이는 정도를 줄이면서 약한 저역 충격과 연타를 보존하고, 게임별 세부 조정을 자동화하는 것이다. DSP Only는 독립 동작해야 한다. 고음만 있는 입력으로 새 햅틱을 합성하지 않는다.

현재 앱은 Studio DSP 8개 값을 읽고 WAV로 PC 게인과 Studio 강도 감소 후보를 계산한다. 실시간 Rear 게인 보정과 유휴 Replace/Rear에서의 강도 감소·복구가 구현돼 있다. 실기기 100% → 99% → 100%는 강도 단일 필드의 근거로만 사용한다. 다음 여섯 항목은 제안된 작업이며 실제 완료 상태는 시험 결과로 갱신한다.

## 1. Studio 저역통과 후 대역 분할

src/audio.cpp의 auto_mode 및 split_on 경로에서 각 채널의 메인 저역통과 출력 fl/fr를 크로스오버 입력으로 사용하고 같은 신호에서 저역을 빼 상위 대역을 얻는 후보를 비교한다. 변경 전 동일 소스의 출력 명령을 기준으로 남긴다. 48 kHz에서 80 Hz 짧은 충격, 600 Hz와 그 이상의 지속음, 좌우 독립 신호를 여러 컷오프·기울기·크로스오버 조합에 통과시킨다. 최종 양자화 전후 피크와 RMS를 함께 기록한다. 분할 해제 경로의 명령 바이트 일치, 고역 누설 감소, 저역 충격 보존이 채택 기준이다. Native Mix에서는 원래 Native 성분을 별도로 확인한다. studio_optimizer_preview.py의 분할 대역 상한 가정도 재검산한다.

## 2. 게이트 응답 측정 및 필요한 계수만 보정

src/audio.cpp의 GATE_OPEN/CLOSE는 48 kHz에서 목표값 변화의 90%에 약 0.22/2.37 ms 만에 도달한다. 주석의 5/60 ms와 시스템 전체의 응답을 구분한다. 임계값 근처에서 진폭이 흔들리는 저음과 간격을 달리한 이중 충격으로 게이트 계수 단독 응답, 최종 진동 명령의 떨림, 두 번째 피크, 감쇠 꼬리를 측정한다. 결함이 재현될 때 해당 방향의 계수만 조정한다. 재현되지 않으면 현행값을 유지하고 주석의 시간 정의를 바로잡는다. 게이트 꺼짐, 무음 복귀, 첫 타격 지연을 회귀 항목으로 둔다.

## 3. 원본 오디오에서 지속 저음과 후속 충격 분리

Studio가 원본 오디오에서 햅틱을 생성할 때 기존 대역 포락선으로 느린 배경 수준과 짧은 상승분을 구분하는 후보를 시험한다. PC가 이미 가공한 Rear 제어 신호는 장치의 활성 세션·경로 정보로 식별해 이 처리를 우회한다. Rear 채널 번호만으로 의미를 단정하지 않는다. 무음, 엔진음 단독, 동일 엔진음에 약한 충격을 얹은 쌍, 지속 진동 자체가 의도된 입력을 비교한다. 배경 RMS, 배경을 뺀 충격 피크, 연속 진동 감쇠량을 함께 기록한다. 배경을 줄인 만큼 타격도 같이 줄거나 의도된 지속음 손실이 크면 제품 기본값으로 채택하지 않는다.

## 4. 게임·장치·프로필별 PC/Studio 공동 후보 계산

studio_optimizer_preview.py의 실측 WAV 비교와 안정된 프로필 읽기를 확장한다. 게임 식별자, 출력 장치, 활성 프로필 리비전, 입력 구간과 사용자 강도를 묶어 기준을 잡는다. 같은 입력을 현행값과 후보값으로 처리해 PC 게인과 Studio 컷오프·크로스오버·대역 게인·기울기·스무딩·게이트·강도의 조합을 평가한다. 캐리어와 Native 혼합은 지원 필드, 의미, 소유권이 확인된 경우에만 후보에 넣는다. 변경량이 작은 후보부터 평가하고, 여러 구간에서 배경·충격·피크 기준을 함께 만족할 때만 선택한다. 근거가 부족하거나 장치가 바뀌면 후보를 폐기한다. 결과에는 필드별 현재값·제안값·선택 이유와 측정값을 남긴다. 게임 전환 시 이전 후보를 재사용하지 않는 모의 시험까지 완료한다.

## 5. 재생 중 제한적 적응

studio_live_output.py와 adaptive_gain.py의 기존 Rear 보정을 재사용한다. 빠른 오디오 처리와 느린 판단을 분리하고 변경 폭·최소 유지 시간·히스테리시스·사용자 상한을 정의한다. 우선 검증된 PC 게인으로 재생 중 대응한다. 펌웨어 필드는 6번의 계약에서 재생 중 변경을 명시적으로 지원하고 안전성이 확인된 항목만 연결한다. 유휴 전용 필드는 다음 안전한 적용 시점까지 보류한다. 오디오 콜백에서 HID 응답을 기다리지 않는다. 일정 신호에서 값이 왕복하지 않는지, 지속 과부하 뒤 회복하는지, 세션 단절과 늦은 응답이 새 게임에 영향을 주지 않는지 검증한다.

## 6. 펌웨어 다중 옵션의 조건부 적용·읽기 검증·복구

기존 강도 명령 0x26과 설정 검증기를 출발점으로 삼는다. 지원 필드·범위·단위·상호 제약·적용 가능 상태를 먼저 문서화한다. PC가 보낸 예상 장치·프로필·리비전·기존값과 펌웨어 상태가 일치할 때만 검증된 후보 전체를 RAM에 반영한다. 일괄 적용 전에 모든 필드를 검사하고, 적용 뒤 실제 필드와 새 리비전을 다시 읽는다. 복구는 같은 변경의 소유권이 유지될 때만 허용한다. 응답 유실 시에는 재전송 전에 상태를 다시 읽고 외부 편집을 보존한다. 자동 슬롯 저장과 하드웨어 안전 한도 상향은 제외한다. 기존 펌웨어는 지원 기능을 확인한 범위에서만 사용한다. 정상 적용·복구, 잘못된 조합, 중복 요청, 외부 편집, 장치 단절, 부분 실패를 호스트 모의 시험으로 검증한 뒤 앱의 게임별 자동화 경로에 연결한다.

## 실행 순서와 인수

1 → 2 → 3의 결과로 DSP 기준선을 확정하고 4에서 공동 후보를 산출한다. 5의 PC 제어를 검증한 뒤 6을 구현하고, 5의 펌웨어 허용 필드를 연결한다. 수동 슬라이더 추가 없이 메인 화면을 간소하게 유지하고, 보류·실패 이유와 읽기 결과는 기존 진단 화면을 사용한다.

각 합성 시험은 변경 전후에 동일 입력·초기 상태·설정·강도를 사용한다. 허용할 타격 손실과 피크 한도는 결과를 보기 전에 기록하고, 구간별 실패도 보고한다. 개발 중에는 변경 경로만 검사하고 최종에 앱 통합 시험, 펌웨어 호스트 회귀, Pico 2 W 및 Windows 앱 빌드를 수행한다. 다중 필드 적용의 순서 충돌을 기존 시험으로 충분히 다루기 어려우면 관련 상태 전이만 형식 검증한다.

최종 보고는 모의 시험, 실기기 확인, 보류 항목으로 구분한다. 명령값과 실제 진동을 따로 기록한다. 실제 게임 A/B, 재생 중 물리 장치 전환, 물리 지연과 학습된 Tiny Causal GRU 평가는 기존 보류 범위로 둔다. 플래시와 신규 실기기 다중 필드 쓰기는 해당 시험에 대한 승인 후 수행한다.
