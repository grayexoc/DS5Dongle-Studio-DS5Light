# DS5Light V3 세부 설정 자동화와 UI 간소화 작업지시서

화면 배치와 수동 다채널 정책은 이후 사용자 결정에 따라 갱신됐다. 현재 화면과 검증 결과는 [진행 기록의 메인 화면 개편](PHASE_STATUS.md#phase-6-main-capture-layout)에서 확인한다.

## 인수 목적

전역 캡처와 프로세스 캡처를 모두 유지한다. 일반 사용자가 캡처 대상과 출력 장치를 선택하면 햅틱을 시작할 수 있게 한다. 채널과 Studio 경로를 결정하는 책임을 앱으로 옮기고, 기존 수동 조정 기능은 고급 화면에서 계속 사용할 수 있게 한다. 기존 Studio 프로필에 저장된 강도와 질감은 사용자 선택으로 취급한다.

## 착수 기준

1. 작업 대상은 이 문서를 담은 저장소의 현재 작업 트리다. 작성 당시 브랜치는 `dev/ds5light-v3-phase2`다. 최초 문서 브랜치나 배포 ZIP에서 시작하면 이후 구현이 빠진다. 다른 환경으로 옮길 때는 미커밋 파일과 신규 파일까지 포함한 작업 트리를 인계받는다.
2. 루트에서 `git status --short --branch`로 기존 변경을 파악한다. `AGENTS.md`, 이 디렉터리의 사양, 특히 `UI_SPEC.md`, `ADAPTIVE_IO_SPEC.md`, `PHASE_1_CONTRACTS.md`, `STUDIO_FIRMWARE_SPEC.md`, `DECISION_LOG.md`, `PHASE_STATUS.md`의 최신 기록을 읽는다. 상태표와 후속 기록이 다르면 현재 코드와 시험 기록에서 확인한다.
3. `DS5Light/app.py`에서 위젯 생성부터 시작·중지 콜백까지 추적한다. `audio.py`, `channel_policy.py`에서 전역·프로세스 캡처의 실제 열기 경로를 찾는다. Studio는 `studio_panel.py`, `studio_optimizer_preview.py`, `studio_live_output.py`, `studio_settings_protocol.py`와 호출자를 확인한다. 프로토콜을 새로 설계하기 전에 기존 임시 적용·읽기·복구 구현을 찾는다.

## 작업 순서

### 1. 설정별 책임을 확정한다

| 화면 표시 | 저장 또는 입력 키 | 적용 주체와 코드 | 위치 |
|---|---|---|---|
| 캡처 방식, 프로세스, 입력·출력 장치 | `scope`, 프로세스 선택, `input`, `output` | PC `App.start` → `Engine` | 오디오햅틱 |
| 채널 구성, 센터, 후방, LFE, 합산 제한 | `channel`, `center`, `rear`, `lfe`, `limiter` | PC 캡처 협상과 `ChannelMixer` | 고급 설정 |
| 억제 필터, 배경 억제량, 충격 보존, 대역 억제, 변화량 보호, 오디오햅틱 세기 | `bypass`, `strength`, `impact`, `background`, `transient`, `gain` | PC `Controls`, DSP, `OutputGain` | 고급 설정 |
| 게임 프리셋과 게임별 자동 적용 | 로컬 프리셋 슬롯과 실행 파일 바인딩 | PC 프리셋 저장소 | 고급 설정 |
| Studio 프로필·슬롯, DSP 소스·강도, 독점 출력 | Studio 설정 필드와 세션의 `studio_live` | Studio DSP/슬롯 및 PC 독점 출력 작업자 | 고급 설정과 Studio설정 |
| 실제 캡처 형식, 폴백과 복구 결과 | 실행 중 관측값 | PC 진단 및 장치 읽기 검증 | 설정·진단 |

현재 노출된 햅틱·캡처 컨트롤에 대해 사용자 표시명, 저장 키, 읽는 코드, 최종 적용 위치(PC 또는 Studio), 이동할 화면을 작업 메모 한 표에 적는다. PC와 Studio에 강도나 게인이 각각 있으면 어느 신호 단계에 작용하는지 확인한다. 화면 이동만으로 값을 초기화하거나 같은 조정을 양쪽에서 중복 적용하지 않는다. 햅틱과 무관한 Studio 기능은 기존 진입 경로를 보존한다.

### 2. 기존 채널 자동 결정을 두 캡처 경로에 연결한다

- **전역 캡처**는 선택한 장치의 루프백을 열 때 확인한 장치 식별자, 채널 수, 샘플레이트, 채널 마스크를 사용한다. 5.1 후면·측면과 7.1은 기존 매핑을 재사용한다. 배치가 불명확하면 기존 첫 스테레오 쌍 처리와 추가 믹싱 제한을 유지한다.
- **프로세스 캡처**는 세션 힌트와 기존 후보 순서를 사용한다. 모노·스테레오 힌트면 2채널, 6채널 힌트면 6→2, 힌트 미상은 8→6→2다. 지원하지 않는 형식이라는 초기화 결과에서만 다음 후보로 넘어간다. 권한 오류나 대상 종료는 원인을 표시한다.
- **수동 설정과 출력 장치**는 기존 수동 선택을 우선한다. 기존 출력 장치를 식별할 수 없고 후보가 여럿이면 출력 선택을 요청한다. 선택한 입력 채널 수와 Studio의 USB 출력 경로는 별개로 관리한다.
- **완료 기준**은 진단에서 요청한 형식, 실제 열린 형식, 폴백 이유를 구분할 수 있는 것이다. 6채널 스트림을 열었다는 결과를 게임이 여섯 채널 모두에 유효 신호를 냈다는 판정으로 표시하지 않는다.

### 3. Studio 자동 적용을 기존 임시 트랜잭션에 연결한다

1. 시작 시 대상 장치와 지원 기능, 현재 설정을 읽는다. 변경 필요성을 판단할 근거가 없으면 장치 쓰기를 생략하고 이유를 진단에 남긴다.
2. 선택한 출력 경로에 필요한 필드만 비교한다. 이미 맞으면 장치 쓰기는 0회다. Replace/Rear는 그 조합을 요구하는 경로에서만 사용한다. 일반 시작·중지에는 슬롯 저장을 연결하지 않는다.
3. 변경이 필요하면 기존 조건부 적용과 읽기 검증을 사용한다. 성공한 변경의 원래 값과 대상 장치를 복구 시점까지 유지한다. 일부 적용 후 시작 실패, 정상 중지, 앱 종료에서 동일한 복구 경로를 사용한다. 중간에 사용자가 값을 바꾸거나 장치가 교체되면 기존 조건부 복구 규칙을 지킨다.
4. 복구 판정은 실제 읽기 결과로 한다. 장치 분리로 확인할 수 없으면 진단에 ‘복구 미확인’을 남긴다. 강도 자동 조절은 기존 활성화 조건과 근거가 있을 때만 사용한다. 새 기본 강도나 프리셋을 만들지 않는다.

### 4. 기본 화면을 줄인다

기본 화면의 조작 순서는 **캡처 방식 → 대상 → 출력 → 시작/중지**다. 전역 모드에서는 프로세스 선택기를 숨기고, 프로세스 모드에서는 실행 대상을 선택할 수 있게 한다. 정상 동작은 현재 대상·실제 캡처 형식·출력을 한 줄로 표시한다. 상태를 아직 읽지 못했으면 확인된 정보만 표시한다.

고급 화면에는 수동 채널, 다운믹스, PC DSP, Studio 경로·강도·슬롯 관리의 기존 컨트롤을 옮긴다. 진단에는 자동 결정 근거와 적용·복구 결과를 둔다. 기존 콜백, 환경설정 키, 번역을 재사용한다. 한국어·영어에서 키보드로 시작·중지와 고급 화면에 도달할 수 있어야 한다. 숨겨진 컨트롤의 초기화나 탭 이동이 장치 쓰기를 유발하는지도 확인한다.

### 5. 변경 범위에 맞춰 검증한다

| 시나리오 | 합격 기준 |
|---|---|
| 기존 프로필을 열고 화면만 전환 | 수동값·프리셋 유지, 슬롯 쓰기 0회 |
| 전역 캡처, 알려진 마스크와 미상 마스크 | 기존 표준 매핑과 보수적 폴백이 각각 유지됨 |
| 프로세스 자동·수동 및 초기화 실패 | 자동 후보 순서, 수동 우선권, 오류별 폴백이 보존됨 |
| Studio 경로 일치 / 불일치 | 일치 시 쓰기 0회, 불일치 시 필요한 변경만 적용하고 중지 후 원래 값 읽기 일치 |
| 부분 실패, 외부 설정 변경, 장치 분리 | 가능한 복구를 시도하고 결과를 구분함. 다른 장치나 이후 사용자 변경에 원래 값을 덮어쓰지 않음 |
| 기본 UI에서 두 모드 시작·중지 | 고급 화면을 열 필요가 없고 모드별 대상 선택과 상태 표시가 실제 동작과 일치함 |

개발 중에는 해당 모듈의 기존 시험부터 실행한다. 예를 들어 DS5Light 디렉터리에서 프로젝트 Python으로 `python -m unittest test_channel_mix` 또는 `python -m unittest test_studio_live_output test_studio_optimizer_preview`를 실행한다. 누락된 분기만 시험을 보강한다. UI 통합 후 전체 앱 회귀와 빌드를 한 번 수행하고, 지원 최소 창 크기와 125% DPI에서 두 언어의 주요 조작이 보이는지 확인한다. 기존 조건부 복구의 동시성 규칙을 바꾸는 경우에만 관련 형식 검증 모델의 재검증 필요성을 판단한다.

## 인계할 결과와 보류 범위

완료 보고에는 기본 화면에서 두 캡처 방식을 쓰는 순서, 기존 설정의 새 위치, 자동화가 결정을 보류하는 조건, 변경 파일, 실행한 빌드·시험 결과를 적는다. 모의 시험, 실기기 읽기 검증, 사용자 체감 확인을 구별한다. 6·8채널 픽스처 결과를 실기기 측정으로 기록하지 않는다.

실제 게임 캡처 비교, 재생 중 장치 전환, 물리 지연 측정은 후속 항목이다. 이번 작업은 로컬 앱 구현과 검증까지다. 새 펌웨어 플래시, 영구 슬롯 변경, 원격 푸시, 공개 릴리스는 별도 승인 범위다. 단계별 재승인 없이 실행 가능한 작업을 순서대로 진행하고, 실기기 개입이 필요한 항목이 생겨도 독립적인 구현과 모의 검증을 먼저 마친다.
