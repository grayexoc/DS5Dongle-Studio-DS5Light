# DS5Light Unified Haptics V3 Phase 1 계약 초안

2026-11-20 사용자 승인으로 채널 소유권, 프레임 식별과 유효성, 설정 적용·복구 계약을 동결했다. 기준은 문서 브랜치 `docs/codex-v3-handoff`의 `0b828f88ce6c65c66077348d6dc34f933a573c33`와 Studio v48이다. 실기기 전용 모드 활성화와 GRU 채택은 각각의 검증 기준을 충족해야 한다.

## 1. 입력과 출력

- 입력 계약은 캡처 범위, 프로세스 ID와 시작 시각 또는 엔드포인트 ID, 샘플률, 샘플 형식, 채널 수, 알려진 마스크, 실제 프레임 배열과 스트림 세대로 구성한다. Windows 형식과 게임 콘텐츠의 배치는 별도로 기록한다. Auto는 메타데이터와 프레임 검사를 우선하고 신호 통계는 보조 증거로 사용한다. 배치가 모호하면 같은 장치와 형식에서 검증한 매핑을 재사용하거나 명시적으로 전면 스테레오만 선택한다. 프로세스 캡처 실패 시 장치 전체 캡처로 전환하지 않는다.
- 출력 계약은 확인된 Studio 엔드포인트에 48kHz, PCM16 LE, 4채널 인터리브 순서 CH0·CH1·CH2·CH3이다. `0x0033`은 USB의 전면 L/R, 후면 L/R 표기다. 후면의 의미는 모드별로 결정한다. 스피커 L/R은 전면 PCM 순서를 뜻하며 내장 스피커의 물리 출력 채널 수를 의미하지 않는다.
- 앱이 전송할 때 전면 PCM의 원본 보존을 약속하는 모드는 PC 억제와 햅틱 세기 처리가 전면으로 새지 않도록 출력 버퍼에서 구분한다. 런타임 마이크·스피커 동작은 Studio의 음소거, Effect Leak, 볼륨, 보드 설정에 따른다.

| 모드 | CH0/1 | CH2/3 | Studio 계약 |
|---|---|---|---|
| 기존 Off | 기존 스피커 경로 | Native PCM L/R | 기존 게인·변환·제한을 유지한다. 자동 DSP는 Off다. |
| 기존 Native 공존 Mix | 전면 PCM과 파생 DSP 입력 | Native PCM L/R | 전면 DSP 소스를 강제한다. Native 레벨과 필터, 변환 럼블은 기존 프로필을 따른다. 앱이 오디오를 전송하는 기존 front-only 보호도 유지한다. 독립 Native PCM을 공급할 수 없는 세션에서 공존 지원을 표시하지 않는다. |
| V3 후면 DSP 전용 후보 | 보존된 전면 PCM | PC 햅틱 제어 신호 L/R | 후면 DSP 소스와 Replace를 조합하는 안을 먼저 검증한다. CH2/3은 Studio 필터·엔벌로프·캐리어의 입력이며 액추에이터 원파형이 아니다. 스피커 보존에는 해당 음소거 정책의 확인이 필요하다. |

기존 앱은 `Mix + rear DSP + Native 레벨 > 0`을 거부한다. 별도 승인 없이 이 검사를 우회하지 않는다. 후면 한 쌍을 점유하는 V3 전용 모드에서 독립 게임 Native PCM의 동시 보존은 범위 밖이다. Replace의 물리 출력과 Effect Leak 상호작용 검증 전에 자동 전환을 허용하지 않는다.

## 2. DSP, GRU, Fusion 및 Mapper 인터페이스

아래는 논리 스키마다. [V1 호스트 교환 스키마](phase1-frames-v1.schema.json)는 Phase 1의 직렬화 검증용 UTF-8 JSON 계약이다. 런타임의 프로세스 내부 표현과 Studio USB/HID 포맷은 각각 이 계약과 독립적이다.

| 데이터 | 필수 필드와 동작 |
|---|---|
| `AudioBlockV1` | `stream_generation`, `first_sample`, `frames`, `sample_rate_hz`, `layout_id`, `channels`, `pcm_s16`, `discontinuity`. `first_sample`은 같은 스트림 세대 내 단조 증가하는 프레임 인덱스다. 캡처 시간은 마이크로초 단위의 단조 시간이며 `capture_source`와 쌍으로 기록한다. |
| `FeatureFrameV1` | `stream_generation`, `profile_revision`, `feature_schema_id`, `sequence`, 분석에 포함된 마지막 `sample_index`, 유한한 float32 특징 배열. 별도 스키마에 특징 이름·순서·단위·정규화·범위를 기록하고 모델 메타데이터와 정확히 일치해야 활성화한다. |
| `InferenceResultV1` | 위 세대·리비전·스키마·시퀀스, `inference_epoch`, `model_id`, 유한한 다중 레이블 확률 배열, `valid`. 배열은 모델 메타데이터의 레이블 순서와 일치하고 각 값은 0–1이다. 워커에 넘기는 특징에도 같은 epoch를 붙인다. |
| `HapticFrameV1` | `stream_generation`, `profile_revision`, `layout_id`, `first_sample`, `frames`, `sample_rate_hz=48000`, `control_lr`. 제어값은 −1~1 정규화 범위이며 L/R 순서로 인터리브된다. Mapper가 유일한 생성자이며 최종 PCM 엔코더가 유한값 검사와 포화 제한을 적용한다. 전면 오디오는 별도 입력으로 전달된다. |

- V1 디코더는 `kind`와 `version=1`을 확인한다. 미지원 버전, 알 수 없는 필드, 누락된 필수 필드, 범위 밖 값은 거부한다. 호환되지 않는 표현을 추가할 때는 새 버전과 별도 디코더를 명시한다. 32비트 세대·리비전·시퀀스는 서로 다른 역할이며, 동일 식별 범위에서 조용히 순환시키지 않는다.
- PCM 배열 길이는 `frames × channels`, 제어 배열 길이는 `frames × 2`다. 프레임 좌표는 동일 샘플 클록에서만 비교한다. 캡처와 출력 샘플률이 다르면 리샘플러가 좌표를 변환한다. 모델별 특징·레이블 배열 길이와 식별자 일치는 해당 메타데이터 확인으로 검사한다. 이런 교차 필드 규칙은 JSON Schema의 형태 검사에 추가한다.
- 추론의 `sample_index`는 대응 특징의 인덱스를 그대로 복사한다. 결과는 현재 세대·리비전·epoch이고, 대응 특징과 모델 ID가 일치하며, 이미 소비한 시퀀스보다 새롭고, DSP 처리 시점에 미래가 아니며 수명 한도 안에 있을 때만 Fusion에 반영한다. 조건을 충족하지 않으면 DSP Only가 계속된다.

기존 `core.Processor`의 인과 필터와 에너지·엔벌로프 계산을 공유한다. 초기 검증 기준은 DSP 240샘플/48kHz와 GRU 10ms 간격이다. 큐는 유한하며 DSP 스레드가 추론이나 장치 설정을 기다리지 않는다. 세대·리비전 불일치, 시퀀스 단절, 초과·지연·스키마 오류 시 AI 결과를 무효화하고 hidden state를 초기화한다. 단일 Fusion은 같은 세대의 최신 유효 결과만 사용하고, 사전에 정한 최대 수명과 워밍업 기준이 충족될 때까지 DSP Only를 사용한다. 최종 특징 목록·레이블·결과 최대 수명은 캡처 자료와 벤치마크로 정한다. TCN과 온라인 학습은 포함하지 않는다.

추론 세션 관리자가 재설정 때 epoch를 올리고 Fusion이 이전 epoch의 결과를 즉시 거부하도록 한다. GRU 워커만 hidden state를 변경한다. 워커는 새 epoch의 첫 프레임 처리 전에 상태를 초기화하며, 실행 중이던 추론 완료에는 시작할 때의 epoch를 붙인다.

## 3. 프로필, 장치 적용과 복구

- PC Unified Profile은 DS5Light 소유 필드의 원하는 값과 리비전을 가진다. Studio의 활성 프로필, 적용 읽기값, Flash 저장 확인은 각각 기록한다. 트리거, 자이로, 매핑, 매크로, 독립 스피커 설정 등은 Studio 소유다. Native 필터와 관련 기본 정책은 이번 초안에서 기존 Studio 프로필을 따른다.
- 기존 Off와 Native Mix에서는 PC가 모드·소스·Native 레벨을 관측하고 기존 front-only 정책에 반영한다. 후면 DSP 전용 후보에서 PC가 일시 제어할 수 있는 초기 필드는 `auto_haptics_enable`, `ah_dsp_source` 두 개로 제한한다. Apply Manager가 진입 전 값을 보관하고 정상 종료 시 복원한다. 음소거 및 다른 설정은 읽고 적합성을 판단하며 별도 승인 없이 쓰지 않는다.
- 가능한 설정은 펌웨어 식별과 실제 필드 읽기로 확인하고 범위·형 교차조건을 검사한다. 기존 `SettingsClient`의 변경 필드 쓰기와 재조회, 별도 저장 ACK를 재사용한다. 적용 경로는 장치와 활성 프로필을 고정하고 장치 작업을 직렬화한다. 이전 값 스냅샷 → 검증 → 변경분 쓰기 → 같은 장치·프로필 재확인 → 필드별 재조회 순서다. 성공 확인 전에는 적용 완료를 표시하지 않는다.
- 부분 실패 시 출력을 보류한다. 장치·프로필 식별이 그대로라면 변경 필드를 다시 읽고 확인 가능한 이전 값만 복원한 뒤 재조회한다. 식별 불일치나 복원 실패는 적용 불명으로 기록하고 자동 쓰기와 전용 라우팅을 보류한다. Flash 저장은 별도 사용자 동작과 ACK로 다룬다. 기존 HID는 이 과정을 원자적으로 처리하지 않는다.
- 기존 HID의 적용 전후 식별 확인만으로 외부 프로필이 A→B→A로 바뀐 경우를 배제할 수 없다. 펌웨어가 쓰기 대상과 활성 프로필의 동시 검증을 지원하기 전에는 외부 설정 도구와 슬롯 전환을 배제할 수 있는 수동 검증 세션에서만 일시 쓰기를 허용한다. 이 전제를 충족하지 못하는 런타임은 읽기 전용으로 운용한다. 활성 슬롯을 확정할 수 없을 때 자동 복원도 보류한다.
- 재연결·형식 변화·활성 프로필 전환 시 이전 스트림 세대와 AI 결과를 무효화한다. 바인딩과 실제 4채널 형식, 모드·소스·Native·음소거 정책을 다시 확인한다. 검증된 동일 계약에서만 재개한다. 확인되지 않은 후면 채널에는 합성 신호를 보내지 않는다.
- 최적화는 확인된 신호 통계와 승인된 범위로 후보를 계산한다. 게임 중 사전 승인된 PC 조정만 제한된 속도로 적용한다. 낮은 신뢰도에서 구조 변경과 펌웨어 안전 한도 변경을 허용하지 않는다. 기존 추천 프리셋은 비교 자료로만 취급한다.

### Studio v48 초기 호환 계약

| 필드 | ID / 형식 / 범위 | 경로 정책 |
|---|---|---|
| `auto_haptics_enable` | `0x12` / u8 / 0 Off, 1 Mix, 2 Replace | 이 문서의 전용 모드 검증에서만 일시 쓰기 |
| `ah_dsp_source` | `0x64` / u8 / 0 전면, 1 후면 | 이 문서의 전용 모드 검증에서만 일시 쓰기 |
| `mix_native_level` | `0x55` / u8 / 0–100% | 관측 및 혼합 충돌 검사 |
| `mix_native_filter` | `0x63` / u8 / 0 Raw, 1 Filtered | 기존 Studio 프로필에서 읽기 |
| `auto_mute_mix`, `auto_mute_replace` | `0x16`, `0x15` / u8 / 각 0–1 | 선택 경로의 스피커 동작 확인 |

필드 ID와 HID 명령 ID는 별개다. 묶음 읽기 `0x0C`, 묶음 쓰기 `0x0B`, 지원되는 단일 필드 쓰기 `0x01`과 실제 값 재조회를 사용한다. 설정 읽기 실패를 값 0으로 해석하지 않는다. 명시적 미지원과 전송 실패·응답 불일치를 구분한다. 필요한 필드가 확인되지 않으면 해당 V3 전용 경로를 차단하고 기존 정책을 보존한다. 쓰기 결과가 부분 적용 또는 불명일 때 동일 쓰기를 맹목적으로 재시도하지 않는다. Flash 저장 명령 `0x02`의 ACK 실패·타임아웃·구형 미지원은 저장 미확인으로 표시한다. RAM 읽기값 일치는 별도로 표시한다.

## 4. 착수와 기능 검증 기준

1. **Phase 2 착수 승인**에는 모드별 소유권, 스트림 세대와 스키마 경계, 부분 실패와 재연결 복귀 규칙의 승인이 필요하다. Phase 2에서는 소스 변경 전 기존 경로와 DSP Only 비교 입력을 고정한다.
2. **DSP Only**는 채널 불명·프로필 전환·재연결·부하에서도 기존 경로와 비교한다. 채널 변환, 직렬화 경계와 지원하지 않는 필드, 부분 적용·역순 응답·재연결은 결정적 호스트 테스트로 검증한다. 기존 테스트로 상태 충돌을 충분히 다루기 어려워질 때 관련 상태 모델만 형식 검증 대상으로 선택한다.
3. **GRU 채택**에는 동일 자료에서 검출 품질 개선, p95/p99와 자원 한도, 지연·순서 오류 시 DSP Only 폴백을 요구한다. 수치 합격선은 기준 측정 이후 승인한다.
4. **Studio 전용 모드 활성화 승인**에는 Replace의 물리 출력, 재연결, 스피커와 Effect Leak, 실제 게임 Native 공존 회귀가 필요하다. 외부 계측으로 물리 onset 또는 가속도를 주장하려면 동기 측정 자료가 필요하다.

Phase 0의 실기기 근거는 대상 한 대의 Off 촉감 유선·무선 각 14/14, Mix 필터 활성·비활성의 동시 신호 양쪽 응답 0/4·3/4, 그리고 Replace의 USB 및 파생 DSP 텔레메트리다. Mix 비교는 단일 저레벨 조건에서 순차 실시했으며 필터 기본값을 변경할 근거로 쓰지 않는다. 정상 종료 후 설정 복원은 확인했으며 링크 단절 중 복원과 물리 지연은 미측정이다.

### Phase 1 호스트 검증 결과

- JSON Schema 왕복 4종과 범위·버전·배열 길이 등 거부 사례 17건을 검사했다. 형태는 Ajv로, 배열 길이는 교차 필드 검사로 확인했다. Ajv는 기존 도구에 포함된 것을 사용했다.
- 추론 결과 수용 규칙의 참조 검사에서 정상 결과 1건을 수용했고 이전 epoch, 세대·리비전 불일치, 중복, 미래·만료 결과 등을 포함한 11건을 거부했다. 이는 계약 규칙 검사이며 실제 워커의 스레드 실행 검증은 Phase 3에 속한다.
- 기존 앱 테스트 `test_studio_settings`, `test_config_save_ack`, `test_profile_events`, `test_process_policy`, `test_capture_clock`, `test_channel_mix`의 98건이 통과했다. 기존 HID 계약과 캡처·채널 처리를 모의 또는 호스트 환경에서 검증했다.
- 제품 코드, 펌웨어와 기기 설정은 수정하지 않았다. 펌웨어 빌드, 실기기 재연결, 물리 지연 및 형식 검증은 수행하지 않았다.
